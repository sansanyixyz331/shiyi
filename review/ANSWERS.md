## 2. listing 的平台与分类是否合适？

- **分类 `utilities`**：合适 —— 它是一件本地工具（记下 → 变卡 → 到点提醒），不是内容/社交/游戏类。
- **平台 `["windows", "android"]`**：**两个都是实测过的平台，如实声明**（官方规则：只列你测过的）。
  - **Windows**：桌面端在官方参考宿主上端到端跑通，有连续录屏取证。
  - **Android**：小米13 真机端到端跑通（读群消息 → AI 出卡 → 确认 → **真发回群** → 到点通知），有整链连续录屏 + 内核日志取证。

> **如实说明（评审需知情）**：Android 上的验证，跑在 **Rinx**（OctoSense 出品的原生 Android 应用）宿主上、以**本地导入 `bundle/`** 的方式完成 —— 这**正是官方 Rinx 赛道指定的运行方式**（Rinx 只支持本地导入）；**不是** OctoSense Home。在此路径上应用功能完整；换到 OctoSense 官方宿主时，则按第 3 问所述**如实降级**。

## 3. 授予的能力与应用可见行为是否匹配？（逐个命名 + 说明为何需要）

`hub check` 打印的授予 = `{storage, model, octos.session.history, matrix.read_messages, matrix.profile, matrix.send_message}`。

| 能力 | 应用用它做什么 | 屏幕上哪里能看到 | 哪个宿主提供服务 |
| --- | --- | --- | --- |
| `storage` | 把造过的卡与偏好写进应用自己的 jail（`memory.json`，上限 256 KiB） | 「长期记忆」区块；点「记下」后条数 +1 | 所有宿主 |
| `model`（服务名 `model.complete`） | 调设备助手当**决策核心**：起人话标题 / 判该不该提醒、提前多久 / 写提醒话术 / 给依据 | 卡上「识别来源 · 设备助手」 | **OctoSense 正式提供** |
| `octos.session.history` | 读助手会话，作为造卡的上下文 | 「助手记忆」区块 | **OctoSense 正式提供**（需人先允许本应用的 agent） |
| `matrix.read_messages` | 读**绑定房间**的最近消息 → 点一条造卡；并每 6 秒自动读一次新消息 | 「从聊天拾意」区块 / 「自动读群消息：开」 | **OctoSense 不提供**；Rinx 提供（官方文档标注 Unverified） |
| `matrix.profile` | 读你在 Matrix 上的名字 → 标出哪条是「你自己发的」 | 「你是 … · 带「（你）」的是你自己发的」 | 同上 |
| `matrix.send_message` | 确认一张卡时，把结论**真发回**绑定的那个群 | 「已把结果发回群 —— 这件事真的办成了」 | 同上 |

**没有任何一项是屏幕上不需要的**。也没有声明 `net` —— 应用本身不直连网络，一切与外部世界的接触都走宿主服务（本地清单 `network.hosts = []`）。

> **必须让评审知道的一条（官方文档原话）**：`matrix.*` 的服务，官方文档
> `PUBLISHING.md`「Exact service names」表的 `Served today` 列写着
> **"No OctoSense host service serves them. Unverified: Rinx … serves them to bundles imported into it."**
> 因此**在 OctoSense 官方宿主上，这三项拿不到服务**。应用对此**是如实降级的**：
> 每一处调用前先 `host.has("matrix.…")`（如 538 / 680 / 1139 行），
> 拿不到就把状态写成「宿主没提供读消息这项服务」之类，**不假装成功、不留假数据**；
> 调用返回失败时同样分 `r.is_ok` 两支如实写（如 1139–1151 行）。
> 这是**有意设计的 fail-closed**，不是缺陷：**没有这些服务时，应用的核心主线照常可用**（见第 7 问）。

## 4. 界面上有没有欺骗性的部分？

**没有。** 逐项核对官方点名的四类：

- **不模仿系统提示 / 系统弹窗**：应用自绘自己的卡面与状态行，从不画成系统对话框。
- **不模仿支付页**：全应用无任何支付/金额提交界面。
- **不模仿登录 / 收集凭据**：`main.splash` 里**没有** `is_password`、没有 `Password` / `NewPassword` / `OneTimeCode`（已 grep 全文件，零命中）。应用从不向用户要密码、PIN 或验证码 —— 需要账号的活都交给宿主自己的服务与它自己的输入页。
- **不冒用其他品牌**：界面文案全部是本应用自己的中文口语，无任何第三方品牌名或仿制外观。

## 5. 源码或数据里有没有读起来像「给助手的指令」而不是「给人的内容」的文本？

**如实回答：有一处，且它是应用自身功能的一部分 —— 调用宿主模型服务时携带的提示词模板**，不是针对评审系统或任何外部 AI 的注入。

- 位置：`main.splash` **882–886 行** `turn_prompt(t)`：

  ```splash
  fn turn_prompt(t){
      return model_task()
          + "务必只回一个 JSON 对象：键和值都用英文双引号，不要解释、不要 Markdown 代码块、不要多余的字。"
          + "要说的话是：「" + t + "」"
  }
  ```

- **为什么这是正当的**：这段文本是作为**参数**传给宿主 `model.complete` 服务的（调用点 929 行），作用是告诉设备助手「按这个 JSON 形状回话」。它是**应用在调用它被授予的能力**，语义上等同于一次 API 调用的请求体，**不指向评审者、不试图操纵任何评测流程**。
- 除这一处外，全仓其余文本（界面文案、记忆文件、注释）都是**写给人看的**：中文口语的状态行、字段说明、来源标注。
- 本仓**不带** `tools.json` / `AGENT.md` / skills（`agent: null`），故不存在「agent 文件」这一类。

## 7. 路由建议

**pass**，并请评审连同以下**知情的边界**一起判断：

1. **它靠什么跑起来**：主提交是脚本应用 `shiyi-live` 0.8.6。核心链路 —— 「一句话 / 一段文本 → 本机识别 → **AI 出卡** → 写长期记忆」—— 依赖 `model` 与 `octos.*`，**这两类在 OctoSense 官方宿主上正式提供**，所以**在官方宿主上能完整跑通主线**。
2. **它什么时候会降级**：`matrix.*`（读群消息 / 认出你 / 发回群）与到点排程（`rinx.schedule`）在 OctoSense 官方宿主上拿不到服务，此时应用**如实标注降级**、绝不假装。手机侧的这条链路需在 **Rinx** 宿主上运行（官方文档亦记载 Rinx 提供 `matrix.*`，但标注 Unverified）。
3. **gate 通过 ≠ 运行时可用**：官方文档明言「Passing the gate is not enough: on every call, the host also checks that it serves the name…」。本应用对每一次可能失败的服务调用都做了 `host.has()` + `r.is_ok` 双重兜底。

**需要评审处置的唯一一点**：如果评测在 OctoSense 官方宿主上进行，请以「主线可跑、群消息相关能力按上述降级」为准，而不要按「三形态全功能演示」的期望去核对 —— 后者需要 Rinx 宿主。除此之外，未见需要拦截或人工复核的问题。
