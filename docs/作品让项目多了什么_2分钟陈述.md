## ⏱ 0:00–0:20 开场 —— 先给结论

> 「拾意」做的是**一件事**：**把一句话，变成一张等你点头的卡**——你确认它才动手；**到了点，它还会主动来找你**；它还**记得你的老规矩**。
> 同一件作品，我们做了**三种形态**：脚本应用、Hub 卡片包、和长在 OctoSense 本体上的系统 app。
> **桌面端和安卓真机端，都已经端到端跑通。**
> 接下来这 2 分钟，我讲的**不是"我们做了多大"，而是"我们的作品让这个项目多了什么"。**

## ⏱ 0:20–1:00 第一件：让官方工具链，在 Windows 上真的能走

> 我们不是挑了一条好走的路——**我们是死磕 Windows 走完的**。一路上撞到的官方坑，我们修完**还回了官方仓库**：

| 我们修了什么 | 官方状态 | 结果 |
|---|---|---|
| **#79** 包路径分隔符（Windows 反斜杠被自家校验拒掉） | ✅ **已合并** | 官方**在我们的分支上又补了一笔**，并写进 **契约 1.5.0 的变更日志** |
| **#80** 盖章与校验不一致（盖了章反被拒） | ✅ **已合并** | 杜绝"签了必被拒"的包 |
| **#83** 被拒只给一张白窗、不给原因 | ✅ **已合并** | 从"空窗无原因"→**宿主画出被拒原因** |
| **#64** Rinx 的 Windows 构建/运行文档 | ✅ **已合并** | 让 Windows 上"能跑起来"这件事**有据可循** |

> 一句话：**"在 Windows 上用官方工具链"这条路，我们把坑填平了，并且填进了官方仓库。**

## ⏱ 1:00–1:30 第二件：把"卡片怎么接宿主"写成能自动核的契约

> 我们还发现：**L0 卡片和宿主服务之间的契约，一直只躺在代码里、没有成文**。
> 我们把它**写成了规范，并配了一个检查器**（**#151**，**+933 行纯新增**）——检查器与官方 Hub 的判定**6 项 6 中**。
> 这不是"多提一个 PR"，而是**把"卡片怎么接宿主"这件事讲清楚、还能自动核**。
> （另修一个隐蔽 bug **#343**：脚本里的 `local_time()` 恒返回 UTC，会把**所有 app 的时间都写错**。）

> ⚠️ 这两条**仍在审核中**（open）——我们说的是"已提交、可复核"，不说"已被采纳"。

## ⏱ 1:30–2:00 第三件：给宿主加一张嘴 —— 让 app 能"说话"

> 最后这件我们最看重：**官方宿主里，"让 app 出声"这件事原本没有**——给 app 的服务只有 `octos.* / model.* / glance.*`。
> 我们**在官方既有的扩展点上，给 OctoSense 宿主接上了系统自带的朗读能力**（用 Android 系统 TTS，不碰内核一行）。
> 于是拾意**到点会自己来找你、把卡念给你听**——从"你看了才知道"，变成"**它来找你**"。
> 这块补丁**基于官方干净源、可一键应用**，随作品一并提交。

## ⏱ 收尾（约 5 秒）

> 「拾意」让项目多了什么？——**一条 Windows 上真能走的路、一份能自动核的契约、和一张让 app 会说话的嘴。**
> 而它们都服务同一件事：**一句话 → 一张卡 → 一次真的执行**。谢谢。
