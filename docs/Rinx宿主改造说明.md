# 宿主可用性改造说明（Rinx · 复赛版）

> 作品跑在**现成宿主**上。本页说明：为了让**没接触过它的人能自己装上、自己用起来**，
> 我方在**宿主侧**做了一轮可用性改造 —— 改了什么、为什么、许可是什么。
> **作品本体（`bundle/`、`apps/`、`octos/`）不依赖这轮改造**：用宿主原版同样能跑通全部功能，只是少了下面的易用性。

---

## 一、为什么要改

改造前，一个陌生用户拿到「宿主 + 应用」，会卡在几件很实际的事上：

| 现象 | 后果 |
|---|---|
| 应用列表里的图标不渲染，一片空白 | 不知道该点哪个 |
| 导入表单要手填**应用包绝对路径**，还要填**房间 ID** | 不知道 ID 是什么，填不出来 |
| 导入过的应用**不留存**，每次都要从头再导一遍 | 每次都得重来 |
| 导入的应用与宿主自带应用**混在一起、无区分，也不能删** | 分不清哪个是自己的；不想用了没法清 |
| 导入表单里的**房间选择是定死的** | 想换个群读，只能重新导入 |

结论：功能是通的，但**对一个没接触过它的人，是“装不上、用不了”**。这一轮改造只解决这件事。

---

## 二、改了什么（逐条）

| # | 改动 | 落点 |
|---|---|---|
| 1 | **换一台电脑也能用**（这一类是"跑得起来"的前提，不是好看）：<br>① **图标等资源**查找兜底 —— 原逻辑只按"编译那台机器的绝对路径"找，换机后**整个界面一个图标都不画**（列表、回退箭头全没有）<br>② **中文字体**查找兜底 —— 换机后中文字变方框<br>③ **小应用脚本评估时限** 64ms → 3000ms —— 59KB 的界面脚本在**慢一点的机器**上会超时被掐断，表现为"应用打开了、整块画面空白" | `makepad` · `platform/src/script/res.rs`（①）· `platform/src/cx_api.rs`（②）· `widgets/src/widget_async.rs`（③） |
| 2 | **列表分界线 + 注明**：上半部分＝宿主自带应用；横线以下＝「你导入的应用（不是宿主自带）」 | `src/miniapps/ui.rs` |
| 3 | **导入的应用三个按钮**：`打开`（直接进应用）／`修改`（进设置：改 API key、看它申请了哪些能力）／`删除`（两下确认，删完还能再导入） | `src/miniapps/ui.rs` |
| 4 | **导入过的应用常驻列表**，不必每次重新导入 | `src/miniapps/ui.rs` |
| 5 | **房间选择挪进应用界面**，打开后随时切换（原来是导入时定死） | `src/miniapps/ui.rs` |
| 6 | **应用包路径自适应**，自动填好，不用手打 | `src/miniapps/ui.rs` |
| 7 | **中英双标 + 就地说明**，关键步骤写清楚 | `src/miniapps/ui.rs` · `resources/i18n/zh-CN.json` |
| 8 | **浅色主题** + 左侧栏图标改**深色**（浅底配浅图标会看不见） | `src/app.rs` · `src/theme.rs` · `src/shared/design_tokens.rs` |
| 9 | **双击后零点击直进**（启动脚本自动打开列表、进应用、跑起来） | 便携物料内的启动脚本 |
| **11** | **新增宿主服务 `rinx.schedule`** —— 作品说“到什么时候提醒”，**宿主负责在那一刻执行**（两端同一套） | `src/miniapps/ui.rs` |
| **12** | **新增宿主服务 `rinx.notify`** —— 到点**弹一条系统通知**（手机走安卓通知） | `src/miniapps/ui.rs` |
| **13** | **新增宿主服务 `rinx.speak`** —— 把一句话**念出来**（手机走安卓 TTS；桌面走系统语音） | `src/miniapps/ui.rs` |
| 10 | 若干小问题：列表下方残留空行、点「打开」时重复写快照、房间下拉与首页列表口径不一致（隐藏的聊天不该出现） | `src/miniapps/ui.rs` |
| **14** | **key 保存反馈**：填完助手密钥后明确显示"✓ 已保存 —— 助手已启用（密钥只存在本机，不外传）"（原来只显示一个语义模糊的 ready） | `src/miniapps/ui.rs` |
| **15** | **导入路径自愈**：应用包路径失效时，按可执行文件所在位置自动重填（换机 / 挪目录后不用手改） | `src/miniapps/ui.rs` |

> **两类改动要分清**：**第 1~10、14~15 条＝可用性**（把"装不上 / 看不见 / 点了空白"变成"双击就能用"）；**第 11~13 条＝能力扩展**（新增三项宿主服务，让“**到点它主动来找你**”在手机上真正成立 —— 作品只声明“到什么时候、弹什么、要不要念”，**在那一刻执行的是宿主**）。
>
> ⚠️ **第 1 条要单独强调**：它修的是**换机（便携包）场景**才暴露的问题 —— 在编译那台机器上**不加也一切正常**，所以最容易被漏；一旦漏掉，别人下载到别的电脑就会遇到"**整个界面没有图标**"或"**应用页整块空白**"（我们已实测复现并逐像素验证修复）。
>
> 说明：第 5、10 条同时把「读哪个聊天」的口径**与宿主首页保持一致**（首页看不到的聊天，这里也不列），避免两边对不上。

## 三、许可与归属

- 宿主为 `hagency-org/Rinx`（应用标识 `org.octosense.rinx`），**Apache-2.0 与 MIT 双许可**；
  我方改动**完整保留上游许可、`NOTICE` 与署名**，未替换或淡化任何上游归属。
- 我方改动分两类：①**可用性改造**（界面 / 列表机制 / 资源查找 / 主题 / 启动脚本）；②**宿主服务扩展**（新增 `rinx.schedule`、`rinx.notify`、`rinx.speak` 三项，供作品按需声明使用）。**未删除、也未改变上游既有行为。**
- **作品本体未因这轮改造而改动**：`bundle/main.splash` 与改造前逐字节相同。

## 四、在哪里拿到

- **改造版宿主**随**便携物料**提供：解压即用、双击启动、免注册；
- 逐文件的源码改动清单见上表；如需完整 diff，可另行提供。

## 五、对复现的影响（如实说明）

- 用**宿主原版**复现作品：**照常可跑** —— 五屏、造卡、长期记忆、确认后发回群，全都在；
- **到点提醒 / 发声**这一类**依赖宿主服务扩展**的能力，取决于宿主是否提供（作品对缺失能力有兜底，不会因此崩）。
- 易用性那部分只降低**上手难度**（从“装不上”到“双击就跑”），**不改变作品的功能边界与能力声明**。

> ⚠️ **两种"换环境就跑不起来"的已知情况（如实写明，附对策）**
>
> | 情况 | 症状 | 根因 | 对策 |
> |---|---|---|---|
> | 用**宿主原版**、在**较慢的机器**上 | 应用**打开了**（标题、房间下拉、`Running` 提示都在），但**正文整块空白** | 宿主默认给"迷你应用脚本评估"设了 **64ms** 硬闸；本作品界面脚本 59KB，慢机器上超时被掐断 | 用**打了本补丁的宿主**（第 1 条第 ③ 点已放宽到 3000ms）；或用性能正常的设备 |
> | **便携包换一台电脑**（直接跑可执行文件） | **整个界面一个图标都不画**（列表、回退箭头全没有，悬停仍有名字）；中文字可能变方框 | 资源查找只认"编译那台机器的绝对路径"，换机后落空 | 用**打了本补丁的宿主**（第 1 条第 ①② 点已补兜底） |
>
> 这两条都**不是作品逻辑问题**：同一份应用脚本在正常环境下完整可用（我们已在真机与第二台干净机器上实测复现并逐像素验证修复）。它们也是**官方原版宿主**的既有行为，因此我们把修复一并收进补丁、随作品提交。
