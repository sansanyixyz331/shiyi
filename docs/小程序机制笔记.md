## 0. 一句话

**Hub app = 一个 Card bundle**（清单 + 卡片 + 数据 + 素材 + 截图）。
提交物**只有 `bundle/`**；源码、脚本、密钥、审查包一律留在 `bundle/` 之外。

## 1. bundle 形状（官方规定）

```text
my-app/
  AGENTS.md                 # 开发约定（给 agent/协作者）
  README.md
  bundle/                   # ★ 唯一提交物
    manifest.json           # 身份/版本/完整性/能力声明
    listing.json            # 商店条目：描述/分类/截图/图标/平台/许可
    page.card               # 卡片本体（Octoscript L0）
    page.data.json          # 布局与数据绑定（可选；无数据可省）
    kit/                    # 该卡片所需全部 kit 文件
    assets/                 # 运行时素材 + 图标
    screenshots/01-main.png # 真实捕获，原生验证后加
```

规则：asset 引用一律**相对 bundle 路径**；不得残留导出机的绝对路径或开发服务器 URL；
**依赖外部 Python / 浏览器控制器的服务流程，必须改造成内嵌运行时**才能成为 Hub app。

## 2. 三条作者路径

| 路径 | 说明 |
|---|---|
| native binaries | 随壳发布，另一套构建流程（非我们） |
| **Card bundle** | ★ 纯卡片应用，无需 Rust 原生代码 —— **我方保底作品走这条** |
| app repo | 作者工作区（含 AGENTS/源码/测试） |

## 3. 工具链（官方 `OctoSense-App-Hub`）

```sh
cargo build --release -p octosense-app-hub   --bin hub
cargo build --release -p octosense-card-host --bin card-host

"$HUB_BIN" stamp ./bundle                       # 盖章：写真实摘要（每次改动都要重盖）
"$HUB_BIN" check ./bundle --allow-unsigned      # 门禁自检（未签名会告警，正常）
"$HUB_BIN" scan  ./bundle --packet ./build/review.json   # 生成审查包（放 bundle 外）

"$CARD_HOST_BIN" --bundle ./bundle --app-data ./.local-state --allow-unsigned --remote
curl "$APP_ENDPOINT/g?raw=1" -o ./bundle/screenshots/01-main.png   # 抓真实帧
curl "$APP_ENDPOINT/quit"
```

要点：
- 未签名 bundle 必须在**宿主工作区**里启动，资源才解析得到；
- 当前 `card-host` **没有发行者密钥选项，且即使 `--allow-unsigned` 也拒签过名的 manifest**；
- **加截图会改变摘要 → 要重盖**；签后任何编辑都要重盖重签；
- 门禁通过 ≠ 跑得起来；原生渲染与输入必须**另外测**（`lab/core/NATIVE-INSTRUMENT.md`）。

## 4. Image-to-AppCard 工作流（官方推荐；AGENTS.md 明确"**不要手写 L0**"）

```
设计图 atlas.png  ──OCR/测量──▶  scenes/crop  ──▶  cards/<id>/page.card + page.data.json
（OpenAI Image API gpt-image-2,     （flow json）      （kit / assets 随之生成）
  例：2400×3456） 
```

`apps/aircon/image-to-appcard-flow.json` 的结构：
```json
{ "schema_version":1, "id":"aircon-fresh-v2", "artboard":[406,776], "locales":["en","cn"],
  "generation": { "atlas":"source/atlas.png", "prompt":"source/prompt.txt",
                  "provider":"OpenAI Image API", "model":"gpt-image-2",
                  "requested_size":[2400,3456], "quality":"high" },
  "scenes":[ {"id":"1","design_id":"aircon-01","directory":"cards/aircon-01",
              "crop":[45,82,512,1084],"surface":"app","title":"好物详情"}, ... ] }
```

每屏目录（`cards/<id>/`）实际内容：
`reference.png` `reference.ocr.json` **`page.card`** **`page.data.json`** `page.design.splash`
`kit/` `assets/` `contract.json` `mapping.json` `mapped.json` `annotations.json`
`semantic-map.json` `semantic-preflight.json` `semantic-audit.json`
`conversion-brief.md` `source-measurements.json` `observations.json` `generation.json`

→ **测量结果落在 `source-measurements.json`，它生成了 `page.data.json` 里的 `placements` 坐标。**

## 5. L0 卡片语法（从 `apps/aircon/cards/aircon-01/page.card` 实读）

```
# ledger <app-id>@<version>
# level: L0
# profile: ui/l0
theme light

copy  text_9_text { class: user-copy, en: "立即购买" }
state buy_control_enabled { shape: bool, initial: true }

component Surface991755d1cfb2(instance: text) {
  view Kit(component: "Surface991755d1cfb2", instance: instance) { slot }
}
component NativeButton02f1d1bd99b4(instance: text, enabled: bool) {
  view Kit(component: "NativeButton02f1d1bd99b4", instance: instance, enabled: enabled)
}

view root Surface991755d1cfb2(instance: "page") {
  Surface18f6d557518f(instance: "screen") {
    Imageec6f4cac3824(instance: "product_photo")
    KitButton5dc7ea8cd583(instance: "buy") { ... }
    Text00fa289e0923(instance: "text_9", text: copy.text_9_text)
  }
}
```

- 组件名是**工作流自动生成的哈希名**（`Surface<hex>` / `Text<hex>` / `KitButton<hex>`），
  因为工作流是从测量结果反向生成 component 的。
- `copy` 的值槽位是 `en:`，值本身可以是中文（aircon 就是 `en: "立即购买"`）。
- 数据/状态/事件语义见 L0 规范：`a2app-l0/framework/l0.md`。

> **修正（2026-09-26）**：哈希名只是**工作流的产出**，不是规范要求。
> 我们手写了五屏（`notes` 用 `eyebrow`/`heading`/`action` 这类语义名），
> 逐屏跑通参考宿主、过门禁。手写的唯一硬约束是 **`page.card` 里每个节点的
> `component` 必须在 `kit.json` 里有同名定义，且在 `page.data.json` 里有 placement**。
> 另：`AGENTS.md` 那句 "不要手写 L0" 后面跟的是 **"unless the app owner asks"** ——
> app owner 自己要求手写，就不在禁止之列。

## 9. 已落实（2026-09-26 实测，逐条有据）

| 早先的疑问 | 实测结论 |
|---|---|
| `hub`/`card-host` 能否在 **Windows** 构建？ | ✅ 能。原生 Rust + MSVC，不进 WSL；产物 `hub.exe` / `card-host.exe` |
| 卡片的 actions/事件如何回传服务层？ | ❌ **Kit 路径不支持事件**：`kit_pack::visit` 只收 `component/instance/part` + 已声明 props + layout + style，多传 `on_tap` 直接报 `xxx has no prop on_tap`。正解是同 aircon：**动作写在卡旁的 `service-actions.json`**，由 Agent 读、由 Agent 决定下一屏 |
| 一屏一个 bundle，还是可以多屏？ | **一个 bundle 一个 `page.card`（一屏）**。多屏 = 多张卡（aircon 就是 12 个 `cards/<id>/`），**屏由 Agent 推** |
| 手写的 L0 卡片要满足什么？ | ① 每个节点必须是 `Kit` 组件；② instance 必须在 `page.data.json` 的 `$kit.placements` 里有 `{component, layout:{x,y,w,h}}`；③ 文字节点必须带 `size` + `font_src`（`crate名:路径`，冒号） |
| 画布该多大？ | **412×892** —— `card-host` 硬编码 `window.inner_size`。抓图 515×1073 是 125% DPI，裁掉自绘标题栏 42 物理像素后，`物理 = 逻辑 × 1.25 - 42` |
| 两个宿主怎么分工？ | `card-host` = **测量式设计**（要坐标，走 kit_pack）——**Hub 提交走这个**；`kit-host` = 纯语义角色 L0（`Surface`/`Col`/`TextTitle`），喂给 card-host 会报 `unsupported measured design node: Column` |

参考宿主有内置 HTTP 仪器（`lab/core/NATIVE-INSTRUMENT.md`）：`/` 协议 · `/snap` 控件矩形 ·
`/click` 真实点击 · `/g?raw=1` 抓图 · `/gq` 抓图并退出 · `/d` 树 · `/log` 日志。
我们用它的 **`/g` 逐屏抓真图**（`build/render_cards.py` 全自动）。
