## 0. 一句话：这里要复现的是什么

**在 Rinx（官方参考宿主）里导入拾意 → 点一条房间消息造卡 → 点"确认" → 这条结论真的被发回你绑定的那个 Matrix 房间。**

- 现象级证据：卡片底部出现 **`已把结果发回群 —— 这件事真的办成了`**；回到房间，**多出一条由你发出的回执**。
- 代码锚点：`bundle/main.splash` 里的 `send_back()`（仓库根；初赛结构下该文件位于 `apps/shiyi-live/bundle/`，行号以当前文件为准）。
  关键契约：服务名 **`matrix.send_message`**，`args {body}`，**需在导入时绑定房间**；`host.request(...)` 回调 `r.is_ok` 决定"办成"还是"如实降级"。

## 1. 三个复跑档次（**前置与耗时如实标注**，按你手头条件选）

| 档 | 你要做什么 | 前置 | 耗时 | 需不需要联网/账号 |
|---|---|---|---|---|
| **L0 · 零工具链**（最省事） | 直接看本仓**现成的原始证据**（连续录屏 + 截图 + 宿主日志 + 房间消息 JSON），逐条对照 | **无** | **约 5 分钟** | 否 |
| **L1 · 自备宿主自己跑**（完整独立复现） | 拿到宿主 → 导入 → 绑定你自己的房间 → 手动跑一遍 | 一个提供 `matrix.*` 服务的宿主（Rinx 需**从源码编译**，见 §3 前置） | 编译数十分钟 + 跑 3 分钟 | 需要一个 **Matrix 账号 + 房间** |
| **L2 · 已有宿主时最小复跑** | 宿主已就绪，只跑"导入→造卡→确认→看群里回执" | 已有 L1 的宿主 | **约 3 分钟** | 同 L1 |

> **口径**：L0 不需要任何工具链就能核对**结果**；L1/L2 是**你自己动手跑出同样的结果**。两个都摆在同一份文档里，你按条件选。

## 3. L1 · 自备宿主完整复跑 · 详细步骤

### 3.1 前置（**诚实标注：这一段省不掉**）
- **宿主**：Rinx。⚠️ **官方预编译包与 Rinx 的 `packaging/octos.lock.json` 钉的内核 commit 对不上 ⇒ 只能用 `tools/package-octos.py desktop` 从源码编译**（Rust 工具链 + 共享 Makepad/Octoscript checkout，见官方 `NATIVE-WORKSPACE.md`）。本方实测的构建产物即该源码树的构建输出目录里的 `rinx.exe`（在你自己的机器上）。
- **一个 Matrix 账号 + 一个房间**：Rinx 用 Matrix 做即时消息。**你自己注册一个账号、建一个房间、并加入即可**（我们演示用的是自建 homeserver `matrix.rinx.chat`；**该服务器关闭了本地注册，请不要指望在那上面注册**，用你可用的任意 homeserver 即可）。
- **Python 3**（可选，用于跑一键脚本）。

### 3.2 步骤（每步：操作 → **期望看到什么**）

| # | 操作 | 期望看到（判据） |
|---|---|---|
| 1 | 启动宿主，开启其遥控口：`MAKEPAD_REMOTE=8799 ./rinx.exe` | 宿主窗口出现；遥控口在 8799（本仓录屏即用此口驱动，便于自动化核对） |
| 2 | 在宿主里**导入** `bundle/`（仓库根）；在 `Room ID to allow` 里填**你自己的房间 ID**（形如 `!xxxxxx:你的域名`） | — |
| 3 | 点 **Review bundle** | 列出**六个服务**并全部 **Allowed**：`storage, model, octos.session.history, matrix.read_messages, matrix.profile,` **`matrix.send_message`**。（**缺 `matrix.send_message` ⇒ 见 §4 失败分支**） |
| 4 | 点 **Run** | app 打开：长期记忆区、读到你房间的消息（条数应**等于你房间里的实际条数**）、输入框、示例 chip、卡片区 |
| 5 | 点一条消息（或示例、或自写一句）→ 点 **造卡** | 生成卡片：识别出时间/地点/类型；卡片上**标注识别来源**（无 AI 服务时写 **`本机规则（不依赖任何服务）`**；宿主提供 `octos.turn.start` / `model.complete` 时写 **`设备助手`**） |
| 6 | 点 **确认**（触发 `send_back()`） | 卡片底部出现 **`已把结果发回群 —— 这件事真的办成了`** |
| 7 | 切回你的房间 | **多出一条由你发出**的 `✅ 拾意已记下 · …` 回执（内容 = 刚才那张卡的结论） |
| 8 |（可选，硬核核对）用 Matrix Client API 拉房间最近消息 | 能查到**第 7 步那条**的 `event_id` / `sender` / `origin_server_ts`——**与卡上说的同一时刻** |

### 3.3 复现所需命令清单（照抄即用）
```bash
# 宿主（先起，且保持它在最前，见 §6 坑1）
MAKEPAD_REMOTE=8799 <你的 Rinx 构建产物>/rinx.exe

# （可选）建演示房间 / 投放素材、真窗口连续录屏 —— 均为本方录制取证时用的辅助脚本，
#          非复跑必需，故不随仓提供。
```

## 4. 判据：怎么算"办成"，怎么算"没办成"（fail-closed）

| 情况 | 系统行为 | 卡面文字 | 是否算通过 |
|---|---|---|---|
| 宿主**有** `matrix.send_message` 且发送成功（`r.is_ok`） | 真发消息进房间 | `已把结果发回群 —— 这件事真的办成了` | ✅ **闭环成立** |
| 宿主**没有** `matrix.send_message`（`!host.has(...)`） | **不发送**，不进房间 | `宿主没提供发消息 —— 结果只留在本机` | ✅ 行为正确（**如实降级，我们不假装发了**） |
| 宿主**调用失败**（`r` 非 ok） | **不重试、不改写** | `没能发回群 —— 结果只留在本机` | ✅ 行为正确（fail-closed） |
| `LET_IT_ACT` 关（只记不发模式） | 不发 | 无发送行 | — 设计模式 |
| `SEND_STANDIN` 开（无宿主本地替身） | 写 `send-stub.json` | `已把结果发回群（本地替身）` | ⚠️ **替身，不是真发**；仅用于无宿主环境 |

> **红线**：**没有 `matrix.send_message` 时，绝不写"已把结果发回群"**——代码里三态互斥，卡面文字与真实动作一一对应。

## 8. 诚实边界（一页说清）

1. **演示房间是我们自建、消息是我们自己投放的**（该服务器关注册，拿不到第二个真人账号）；但**读消息 / 判定 / 回执这条链是真的**，代码里无 mock、无硬编码文本（读到的条数随房间变）。
2. **识别路径按宿主能力自动选择**（`ASK_MODEL` 自 0.8.6 起为 **`true`**）：按 `octos.turn.start`（**含内核的 Rinx 包**自带）→ `model.complete`（**OctoSense 宿主**提供）→ **本机规则** 三级探测，谁在找谁，卡上**如实标注**这次走的是哪条（「识别来源 · 设备助手」/「本机规则」）。
   - **演示的手机正片**走的是 `octos.turn.start`，卡上标「**设备助手**」；
   - **Rinx 不把 `model.complete` 授给迷你应用**（宿主顶栏原文 `Mini app was not granted model.complete`）⇒ 我们**不硬调**它；
   - 若你复跑用的 Rinx 构建**不含内核**（没有 `octos.turn.start`），它会**如实退到本机规则** —— 一样出卡，只是没有 AI 标题与提醒建议，**我们不假装接了模型**。
3. **发送端只有一次真发**（§7 那条事件）；"发回群"是**这一个动作**的真实性证明，不含"多方群聊"。
4. 本文**未改动提交物任何字节**；`bundle/` 摘要与签名保持与被评审的 tag 一致。
