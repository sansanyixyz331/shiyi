# 手机端复现说明（Android · Rinx 宿主）

> **这份是给"想自己把手机端跑起来"的人看的**（评委 / 复核者）。
> 手机端的演示能力（真读群消息 → 出卡 → 确认真发回群 → 到点通知并念出来）跑在 **Rinx 宿主**上。
> **两条路**：
> ① **不编译** —— 直接用 [`../android/README.md`](../android/README.md) 里的**现成安装包**（宿主 APK 分卷，含 AI 内核；另附拾意应用包）。
> ② **自己编** —— 本文下面是从源码到真机的完整路径。
> （形态③"原生宿主扩展"按官方口径交**可构建版本 + 复现说明**；`android/` 的现成包是为**方便复核**另附的。）
>
> 桌面端的复现见 [`可独立复跑_发回群闭环_步骤说明.md`](可独立复跑_发回群闭环_步骤说明.md)。

---

## 1. 手机端跑的是什么

| 层 | 是什么 | 从哪来 |
|---|---|---|
| **宿主** | **Rinx**（Android 版） | 开源项目 `hagency-org/Rinx`（**官方 CI 未发布 Android 包** ⇒ 需自行编译，见 §3） |
| **应用** | 本仓库根 **`bundle/`**（脚本应用 `shiyi-live`） | 本仓库 |
| **绑定** | 导入时填一个 **Room ID**（消息发往哪个房间由它决定，卡片决定不了） | 操作时填 |

> **形态对应**：手机端演示走的是**形态①"脚本应用"**（同一份 `bundle/`，与桌面主提交**同一份代码**）。
> **形态③**（OctoSense 系统 app）的宿主扩展构建见 [`../octos/host-extension/`](../octos/host-extension/README.md)。

---

## 2. 为什么需要自己编 Rinx

- Rinx 的**桌面**预编译包与它 `packaging/octos.lock.json` 里钉的内核 commit **对不上** ⇒ 官方桌面预编译包开不起来，**只能从源码编译**（见官方 `NATIVE-WORKSPACE.md`）。
- Rinx 的 **Android 包**官方未发布 ⇒ 需要自己用 `cargo-makepad` 打包（见下）。

**前置环境**（与官方 Makepad/Rinx 要求一致）：Rust 工具链、JDK、Android SDK（build-tools 33.0.1 / platform android-35）、**完整版 NDK**（`aws-lc-sys` 需要它的 CMake toolchain）。

---

## 3. 编 Rinx Android 包（关键步骤 + 一个必踩的坑）

> **只想把它跑起来、不想编译？** 用 [`../android/README.md`](../android/README.md) 里的现成包，本节与 §4 可跳过。

### ⚠️ 唯一的硬坑：打包器与宿主必须是**同一版 makepad**

Rinx 的 Java 打包器（`cargo-makepad`）与它编出来的 native 必须来自**同一版 Makepad**。
如果打包器来自官方树的另一版 ⇒ **APK 能装、能启动、但一碰屏幕就闪退**（Java 层与 native 层不匹配）。

> **正确做法**：用 **Rinx 自己 pin 的那版 Makepad** 编出 `cargo-makepad`，再用它打包。
> （本项目实测：用 Rinx pin 版编出的打包器，一次通过；用官方树另一版的打包器，必崩。）

### 命令（脱敏，路径请替换为你本机的）

```bash
# 0) 环境（示例；按你的机器改）
export JAVA_HOME=<你的 JDK>
export ANDROID_HOME=<你的 Android SDK>
export ANDROID_PLATFORM=android-35
export ANDROID_BUILD_TOOLS_VERSION=33.0.1
export NDK=<你的完整版 NDK>
export CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER="$NDK/toolchains/llvm/prebuilt/<host>/bin/aarch64-linux-android26-clang"
export CC_aarch64_linux_android="$CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER"
export CXX_aarch64_linux_android="${CARGO_TARGET_AARCH64_LINUX_ANDROID_LINKER}++"
export AWS_LC_SYS_CMAKE_BUILDER=0
export CMAKE_TOOLCHAIN_FILE=<NDK 的 android.toolchain.cmake>

# 1) 用「Rinx pin 的那版 makepad」编出打包器（一次即可）
#    在 Rinx 依赖里 pinned 的那份 makepad 目录内：
cargo build --release -p cargo-makepad
#    产物：<makepad 目录>/target/release/cargo-makepad(.exe)

# 2) 用该打包器打 Rinx 的 Android 包
cd <Rinx 源码根>
"<makepad 目录>/target/release/cargo-makepad" makepad android \
  --sdk-path=<你的 Android SDK> \
  --abi=aarch64 \
  --package-name=org.octosense.rinx \
  --app-label='Rinx' \
  build -p rinx --release
#    产物：<Rinx 源码根>/target/android/makepad-android-apk/rinx/apk/rinx.apk
```

> 说明：`--abi=aarch64`（现代手机均为 arm64-v8a）；如需内核能力（`rinx.notify` / `rinx.speak` 等），
> 需把 `liboctos` 内核一并打进包内 —— 本项目实测的含内核包约 **120MB+**，不含内核约 **80MB**。

---

## 4. 装上、导入、绑定房间

```bash
# 装机（替换 <device> 为你的 adb 设备号）
adb install -r <Rinx 源码根>/target/android/makepad-android-apk/rinx/apk/rinx.apk

# 把本仓库的 bundle 推到手机，再在 Rinx 里导入（也可直接从手机文件选）
adb push bundle /sdcard/shiyi-bundle
```

手机上：**左栏「Mini apps」→「Import an app」→ 选 `bundle/` 目录 →
在 `Room ID to allow` 里填目标房间 → 「Review bundle」（应列出已授权能力与房间）→ 「Run」**。

> ⚠️ **发到哪个房间不是卡片说了算** —— 是**导入表单里填的那个 Room**。
> 不填 ⇒ 调用回 `not attached to a room`。

## 5. 已知限制（如实）

- **`matrix.*`（读消息 / 档案 / 发消息）与 `rinx.schedule`（到点排程）由 Rinx 提供**；
  **官方 OctoSense 宿主不提供这些服务** ⇒ 在官方宿主上运行时**如实降级**、不假装（见 `review/ANSWERS.md` 第 3 问）。
- 手机端**未在 OctoSense Home 宿主上验证**；`listing.platforms` 里的 `android` 指**实测过的运行路径**（真机 + Rinx 本地导入）。
- 装机若提示"未知来源 / 未知发布者"：在系统设置里允许一次、或选「仍要安装」。
