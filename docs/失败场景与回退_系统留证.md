## F1 · 准入未授：卡片包未签名

| 项 | 内容 |
|---|---|
| **触发** | 未签名的 `bundle/` 送进要求签名的宿主 |
| **实测** | `admitted=false`、`refused=true` |
| **宿主日志原文** | `card-host: refused: app shiyi is unsigned and this host requires a signature` |
| **证据** | `build/_evidence/neg_unsigned.log` · `build/_evidence/neg_unsigned.png` |
| **用户看到** | 宿主画它**自带的**「拒绝说明页」（21971 字节，含 refused 原文）——**不是本作品卡片** |
| **本作品反应** | **一张卡都不渲染**（fail-closed），不降级显示、不画残缺页 |
| **怎么复现** | `python build/verify_flow.py`（含此用例） |

## F2 · 准入未授：摘要不符（包被改动）

| 项 | 内容 |
|---|---|
| **触发** | 改动 `bundle/` 内容后摘要与 manifest 不一致 |
| **实测** | `admitted=false`、`refused=true` |
| **宿主日志原文** | `card-host: refused: bundle digest 6e63b91c… does not match the manifest's 00f59a1b…: app shiyi version 0.3.3` |
| **证据** | `build/_evidence/neg_tampered.log` · `build/_evidence/neg_tampered.png` |
| **用户看到** | 宿主自带的拒绝说明页（33369 字节） |
| **本作品反应** | **一张卡都不渲染**（fail-closed） |

> ⚠️ **判据怎么读**（这条容易被误读，写在前面）：
> **只看宿主日志的 `admitted` / `refused`**。
> `[SPLASH] eval` **不是**判据——宿主被拒后画的拒绝说明页**也会打这一行**，那是宿主画的、不是本作品卡片。

## F3 · 服务缺失：设备助手（AI）不可用

| 项 | 内容 |
|---|---|
| **触发** | 宿主不提供助手会话服务 |
| **实测** | 卡片**照常渲染**，首屏那行助手答案**不显示**——**不报错、不阻塞** |

## F4 · 服务缺失：模型服务不可用

| 项 | 内容 |
|---|---|
| **触发** | 宿主不提供 `model.complete` |
| **实测** | 识别改走**本地规则兜底**，卡片**自己标注**走的是哪条路 |
| **证据** | `docs/evidence/assist-memory/03-model-fallback-with-card.png` · `docs/evidence/model-path/`（`payload-sent-to-model.json` + `fallback-in-card-host.png` + `model-standin-in-card-host.png`） |
| **用户看到** | 卡片正常出，且**如实标注**来源（模型 / 本地规则），不冒充 |
| **本作品反应** | 两条路都留证，**不隐藏"这次是兜底"** |

## F5 · 能力被拒：脚本派发工具这条路走不通

| 项 | 内容 |
|---|---|
| **触发** | 尝试走"脚本应用派发工具调用"这条路 |
| **实测** | 宿主**硬拒** |
| **宿主源码原文** | `script_apps.rs:237` —— *"this host does not support script tool dispatch"* |
| **证据** | 源码行号 + 原文（见 `docs/回归清单.md` 第 5 项） |
| **本作品反应** | **改道**：不碰内核，改用官方预留扩展点挂工具（`shiyi.repin`），形态③因此跑通 |
| **为什么记这条** | 它印证了一个判断：**不改内核也能做到**，代价是要绕路。这是"技术深度"的正面证据，不是缺项 |

## F6 · 能力被拒：`model` 能力名 ≠ 服务名

| 项 | 内容 |
|---|---|
| **触发** | 在 **Rinx** 上调 `model.complete`（Rinx 不提供该服务；Rinx 给的是 `octos.turn.start`） |
| **实测** | 调 `model.complete` **必被拒**，且顶栏**常驻提示** |
| **证据** | `docs/回归清单.md` 能力表 + 能力矩阵实测记录 |
| **本作品反应** | **不硬调**：0.8.6 起按 **`octos.turn.start`（Rinx 自带）→ `model.complete`（OctoSense 给）→ 本机规则** 三级探测，谁在找谁 ⇒ **两个宿主都不降级**（OctoSense 走 `model.complete`、Rinx 走 `octos.turn.start` —— 两条正片即是）；都不在才退本机规则并在卡上如实标注 |
| **为什么不假装能用** | 红线是**不假装成功**。某条路调不通就换下一条，都不通就如实标注"本机规则"，不硬撑 |

## F7 · 无网络 —— 该 app 根本不用网络

| 项 | 内容 |
|---|---|
| **触发** | 设备断网 / 宿主连不上外网 |
| **依据（实证）** | 根 `bundle/manifest.json` → **`network.hosts: []`** —— 声明**不访问任何主机**，app 自身**不发网络请求** |
| **实测预期** | 出卡、写记忆、快览屏钉卡**都不依赖网络** ⇒ 与有网络时一致 |
| **AI 那一跳** | `model.complete` 走**宿主**；宿主不服务 / 连不上时 ⇒ **按 F4 降级到本地规则**，卡上如实标注 |
| **用户看到** | 卡照常出；若 AI 不可用，卡上标的是"本地规则"，**不报网络错、不假装 AI 成功** |
| **证据强度** | **manifest 实证**：`network.hosts: []` —— 声明**不访问任何主机**，可当场核；出卡 / 写记忆 / 快览屏钉卡**都不经过网络** ⇒ 断网与有网表现一致 |

## F8 · 空数据 —— 空就如实说空

| 项 | 内容 |
|---|---|
| **触发** | 绑定房间里**没有消息**；或设备助手**会话为空** |
| **实测** | 助手会话为空时，界面**如实写"助手会话是空的"**（不编一条凑数）；脚本应用是**有消息才出卡**，没消息时不硬造 |
| **证据** | `docs/evidence/chat-read/00-rinx-reads-room.png`（同一屏里：读到 4 条房间消息 + `助手记忆 · 助手会话是空的`——**空态如实显示**）；「`octos.session.history` 空会话如实显示，不编」见 `docs/evidence/chat-read/README.md` |
| **用户看到** | 没有可拾取的东西时，**界面上就是没有**；不出现"凭空长出来的一条" |
| **本作品反应** | **no-facts 红线**：空就是空，宁可空着也不编 |
| **证据强度** | **实证**：空会话态有截图 —— `docs/evidence/chat-read/00-rinx-reads-room.png`（同屏既读到 4 条房间消息、又显示「助手记忆 · 助手会话是空的」） |

## 仍需人工处理的步骤（官方点名要写）

| 步骤 | 为什么必须人来 |
|---|---|
| **确认并执行** | 每一张卡都要人点"确认"才写记忆 / 才发消息。**我们故意不自动化这一步**——不替用户拍板 |
| **识别不出的部分** | 说不出来的字段**宁可问一句，也不猜**（no-facts 红线） |
| **失败后的处置** | 消息发不出去 → 如实回退"只留本机"；**由人决定要不要重试** |
| **完整复现** | 宿主须从 Rust 源码编译（见 `README.md §8.0`）——这一步我们省不掉，也不假装能省掉 |
