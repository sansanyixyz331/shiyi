## 2. 演示房间与消息来源（**如实交代**）

- 房间：`拾意 · 生活备忘`（6 条）、`拾意 · 出差前收拾`（3 条），建在演示者自有的 Matrix 账号 `@sansanyi331:matrix.rinx.chat` 上。
- 消息**由演示者本人投放**（`_mk2.py` 走 Matrix Client API 逐条发），**不是**第三方真实业务数据。
- ⚠️ 该 homeserver **关闭了本地注册**（`M_UNKNOWN`：`Local registration is disabled while delegated authentication is enabled`），所以**拿不到第二个真人账号**，房间里成员只有 1 人。
- ⇒ 结论：**不要把它说成"真实群聊"**。正确说法是「**自建演示房间，模拟会话流**」。

## 3. 三条链路，哪条真、哪条是搭的

| 环节 | 真实性 | 证据 |
|---|---|---|
| **读取** | ✅ **真**。真走 Matrix 协议拉房间事件，代码里无 mock、无硬编码文本 | 卡面「从聊天拾意 · 读到 N 条消息」；N 随房间实际条数变化（6 条 / 3 条） |
| **识别** | ⚙️ **本机规则**（非大模型），卡面**如实标注**「识别来源 · 本机规则（不依赖任何服务）」 | 见 §4 实测 |
| **确认→回执** | ✅ **真**。确认后调用 `matrix.send_message` 把结论发回该房间 | 房间里真多一条 `✅ 拾意已记下 · 周一 · 10月12日`（时间戳即录制时刻），由绑定账号发出 |

**一句话口径**：*"消息是我们自己投放的；但读、判定、回执这条链是真的，没有任何一处 mock。"*

## 4. 为什么识别走规则（有实测证据，不是回避）

`main.splash` 的 `recognize()` 有三态：`model` / `rules` / `model-standin`。默认 `ASK_MODEL = false`。

2026-10-08 实测（**已把开关打开跑过一遍**）：在 Rinx 导入页挂了本机 provider（`deepseek` / `deepseek-v4-flash` / 正式 base_url / 有效 key）并点「Use this device」、`manifest.capabilities` 里也声明了 `model` —— 结果：

```
宿主顶栏原文：Mini app was not granted model.complete
卡面原文：    识别来源 · 本机规则（宿主没提供助手，已走本机规则）
```

⇒ Rinx（card-host）**不把 `model.complete` 授给迷你应用**，所以本机演示**只能**走规则。据此把开关**改回 false**，并把这段经历写进代码注释与 `listing.json`（`model stays off (Rinx refuses model.complete)`）。
**没有编造"已接大模型"。** 真接了模型的现场只有 OctoSense shell（它有 `model.complete`，但它**没有** `matrix.*`，读不到消息）——两个宿主各缺一半，见 §6。

## 5. 评委可能怎么问 → 怎么答

| 追问 | 标准答法（都不撒谎） |
|---|---|
| 这些消息是真实的吗？ | 不是。是我们为演示自建的房间、自己投放的消息；但读/判定/回执是真的。 |
| 凭什么说"真读"？ | 读到的条数随房间变（6 条/3 条）、内容逐字与房间一致、换房间立刻变；代码里没有硬编码文本。 |
| 是不是正则匹配？ | 是，本机规则（离线、零成本、可预测）。卡面自己写着"识别来源 · 本机规则"。 |
| 那还算 AI 应用吗？ | 识别层设计了 LLM 分支（`model.complete`），宿主提供就自动切、失败自动回退；本机宿主不给这个服务，所以落在规则。 |
| 房间里只有你一个人？ | 是。该 Matrix 服务器关闭了注册，拿不到第二个真人账号；多成员群聊走同一份代码。 |
| 确认之后真的发生什么了？ | 真发了一条消息回房间（可当场在房间里看到那条 ✅ 回执）。 |
| 离线能用吗？ | 能。规则识别 + 本机记忆全在本地；只有"读房间/发回执"需要 Matrix。 |
| 换台电脑能跑吗？ | 能。bundle 是标准的，`hub check` 通过；宿主用 Rinx/OctoSense 桌面端。 |

## 6. 宿主能力矩阵（为什么不能两全）

| 宿主 | `matrix.read_messages` / `send_message` | `model.complete` | 装的拾意 |
|---|---|---|---|
| **Rinx**（`rinx.exe`，遥控口 8799） | ✅ 有 | ❌ 不授予 | **0.7.4** |
| **OctoSense**（`octosense.exe`，8399） | ❌ 无（源码无 `matrix.*`） | ✅ 有（可配 DeepSeek） | 0.2.0（旧手输版） |

⇒ 本演示选 **Rinx**：因为"读消息→回执"是这次的主叙事，而它只有 Rinx 能给。

## 8. 两个必须记住的坑（否则重录必失败）

1. **焦点被抢 ⇒ 遥控输入全死**：一旦别的窗口（如 OctoSense）拿到前台，Rinx 的 `/m`、`/k` 全部无响应（连打字都不进），**必须重起 Rinx**。
2. **输入框不清空就 type 会拼接**：填路径/房间号前必须点最右端 + 连发 Backspace 清空。
