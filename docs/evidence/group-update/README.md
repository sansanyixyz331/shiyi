## 这条链怎么跑起来的（机制）

- app 内 **`start_interval(3.0, watch_poll)`** —— **每 3 秒**读一次收件箱；
- 桌面/真机都能走本地收件箱 `group-inbox.json`（`{messages:[{sender, body, ts}, …]}`）；`WATCH_REAL=true` 时读**真房间**；
- 消息命中**状态变化口令**（`改到/改成/改在/推迟/延后/提前/取消…`）⇒ 找卡（按指代/地点匹配）⇒ **原地更新同一 `card_id`**（不是又长一张）＋ 写留痕（`pw/pp` = 改之前的旧值）＋ **重排提醒**。

## 中间撞出的真 bug 与治本（简述）

- **症状**：`改到下午三点` 这类高频话术，**新时间被当成地点**（`where_of` 把「到」当地点介词；`when_of` 只认阿拉伯数字钟点，抓不到「三点」）。
- **连锁**：地点被污染后，后续按「协和那个」匹配**再也找不到那张卡** ⇒ **一次污染 = 永久失配**（功能失效，不是显示问题）。
- **怎么治本**：时间词表归一（中文数字 / 阿拉伯 / 冒号 / 半·刻）、`when_of` 补"先抓带钟点、再退纯日期"、`apply_update` 加"新地点像时间就丢弃"的撞车保护。
- **验法**：把 `when_of / where_of / when_epoch` 在 Python 里**一比一复刻**跑差分 —— **修前 18 条用例翻车 11 条、6 条排程排不出 3 条；修后全 0**；再重打 APK 装回真机复验。
- **完整记录**（含投放原文、`picks.json` 逐字段、代码行号、三种修法成本对比）：
  本轮验收的详细记录留在本地工作区（不随仓）；本目录的截图 / `picks.json` / 日志即仓内可核部分。

## 怎么复现

```bash
# 1) 把一条"改期"消息放进 app 的收件箱（真机需在 app 数据目录；桌面放 app 数据根）
echo '{"messages":[{"sender":"张姐","body":"协和那个改明天下午3点就行"}]}' > group-inbox.json
# 2) 等最多 3 秒（watch_poll 周期），看 picks.json 的 when / where / pw / pp
#    期望：when = 明天下午3点（…）；where = 协和医院；pw = 改之前的旧时间（留痕）
```

> 桌面版「录一镜到底」的脚本（含遥控口驱动）为本方录制时所用，未随仓提供。

## 边界（诚实）

- 本轮取证时真机为**已 root**（便于 adb 直接投递收件箱文件）；**未 root 的机器上，这条链同样成立**——只是"投递消息"这一步要换成"真房间（`WATCH_REAL=true`）"。
- 图里的 `group-inbox.json` 是**本地收件箱（stand-in）**，不是真 Matrix 房间；**读真房间**那条路走 `matrix.read_messages`（见 `docs/evidence/act/`）。
- **演示加速**只影响"等多久"，**真实提醒时刻照样写在界面上**（图中「到点提醒 · 已提醒过（10月11日 15:00 的事）」即真实时刻）。
