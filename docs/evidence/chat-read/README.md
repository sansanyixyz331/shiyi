## ★ 先读：`demo-rinx-loop.mp4` 的制作方式（如实说明）

`demo-rinx-loop.mp4`（27.5 秒 / 1280×800 / 30 fps）**不是一段连续屏幕录制** ——
它是把**逐步拍下的帧序列**按时间轴合成成片的（**帧序列拼接**）。

**判据（可自行复算）**：全片 **825 帧里只有 203 个唯一帧**，同一画面按固定间隔重复
（例如第 672/676/680… 帧内容完全相同）。也就是说它的"有效帧率"远低于名义的 30 fps。

**为什么这样处理**：这条链路当时是用**逐步抓帧**的方式取证的（每一步抓一张），
而不是开录屏——所以成品只能由帧序列合成。

**想看成片（连续真录屏）请看这两段**（都是宿主自带遥控口驱动、无人手介入、**一段连续真实录屏**）：

| 录屏 | 时长 / 分辨率 | 覆盖 |

| [`../live-run/rinx-live-end-to-end.mp4`](../live-run/rinx-live-end-to-end.mp4) | 20.7s / 1316×1436 | Review 5 服务 → Run → 读房间 → 造卡 → 确认 → 记忆 0→1 |

## 对应能力

- `matrix.read_messages` —— 读**绑定房间**的最近消息（只能读被授权的那个房间）
- `storage` —— 长期记忆（`memory.json`）
- `octos.session.history` —— 读设备助手会话（空会话如实显示，不编）

完整能力清单与出厂开关见 [`../../apps/shiyi-live/README.md`](../../apps/shiyi-live/README.md)。
