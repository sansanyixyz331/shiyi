# 手机端 · 「群里来消息，它自己读到」· 真机实证 + 演示片

> **2026-10-12 · 小米13（`f40f11dc`）· Rinx 宿主（本地构建）· 应用版本 0.8.6**
> 本目录证四件事：**① 群里真来一条消息（不是往应用里打字）② 它自己读到、自己造卡 ③ 确认后真发回群 + 排好到点提醒 ④ 到点真弹通知**。
> 全部对实物取证（界面截图 + 房间消息真投递 + 成片），未修饰。

---

## 1. 这份证据要回答的质疑

**"消息是不是你们自己填进去的？"** —— 不是。演示里那条消息是**从外部真投递进群**的：
走 Matrix 的 client-server API 往应用绑定的房间发一条 `m.room.message`，与"群里有人发了句话"在链路上是同一件事
（跟桌面线用 SMTP 往邮箱真投一封信是同一个做法）。

**"是不是要人点一下它才读？"** —— 不是。应用跑起来后会**自己每隔 6 秒看一次群**：
界面上那行「自动读群消息：开 · 群里来新消息，它自己读到就造卡（已看 N 次）」里的 N 就是它自己看了几次。

---

## 2. 链路（谁做什么）

| 步 | 谁 | 做什么 |
|---|---|---|
| ① | 外部 | 往应用绑定的房间**真投递**一条消息 |
| ② | 作品 `main.splash` | **自己轮询**读到它（只处理"最后一条变了"的；首启只登记基线） |
| ③ | 宿主（手机） | 把这条消息交给设备助手（`octos.turn.start`）→ 回一段 JSON |
| ④ | 作品 | 把 JSON 落成一张卡：**类型 / 人话标题 / 时间 / 地点 / 要不要提醒 / 到时说什么 / 依据** |
| ⑤ | 用户 | 点「记下来」确认 |
| ⑥ | 作品 → 宿主 | `matrix.send_message` 把结论**真发回群**；`rinx.schedule` **排到点提醒** |
| ⑦ | 宿主 | 到点弹**系统通知**并（开关开着时）**念出来** |

**一句话**：**读是它自己读的，写是宿主写出去的** —— 应用声明意图与话术，宿主负责执行。

## 5. 如实说明（边界在哪）

- **"到点"用了演示压缩**：卡上算出的**提醒规则、提前量、到时说的那句话**都是真的；只是把"等到那一刻"在演示里压短，否则要等一整天。成片用字幕交代了这一点。
- **能读的只有它自己被授权的那一个房间**：应用在导入时绑定房间，读/写都只对这一个房间；不是"能读你的聊天软件"。
- **弹通知与发声是宿主的能力**：应用只声明"弹什么、念什么"；宿主没这项能力时，应用**如实标注**而不假装（fail-closed）。
- **应用版本 0.8.6** 与主提交（仓库根 `bundle/`）**同一份 `main.splash`**；两者的区别只在 manifest 的**能力声明**（手机壳另提供 `rinx.*`，主提交只声明官方宿主具备的能力）。
