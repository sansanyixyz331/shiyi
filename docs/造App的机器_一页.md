# 造 App 的机器 —— 一页说明

> **一句话**：拾意不只交一张卡，它交**一台"把意图变成卡"的机器** —— 一条命令，从
> 一句话走到「通过官方门禁的 L0 bundle + 渲染出图 + 自评修订记录」。

---

## 一、怎么用（一条命令）

```bash
python build/pipeline.py --samples --out build/_gen     # 生成 → 自评 → 渲染 → 字体 → 视觉 → 门禁
python build/gen_screens.py --text "…" --verify         # 一条消息 → 五屏 + 渲染 + 视觉自评
python build/demo_identify.py --samples                 # 同一句话：规则 vs 模型 的识别对照
```

（`--model` 走本机模型那条路；不带则走本地规则。默认行为不变。）

## 二、它由什么组成（六样能力，都有实物）

| # | 能力 | 落点 | 状态 |
|---|---|---|---|
| ① | **识别（模型优先 / 规则兜底）** | `src/intent_model.py` + `src/host_local.py` | ✅ 两条路都能出卡 |
| ② | **长期记忆** | `src/memory_store.py`（读真文件，非写死） | ✅ |
| ③ | **契约 + 适配器** | `INTENT_ADAPTERS`：一种意图一条声明，加新意图不改核心 | ✅ |
| ④ | **自评 → 修订** | `selfcheck()`/`revise()`（几何）+ `visual_review.py`（像素） | ✅ |
| ⑤ | **自动化工具链** | `build/pipeline.py` | ✅ |
| ⑥ | **应用造应用** | 生成器自身：一个 app 从一句话造出另一个 app 包 | ✅ |

## 二·五、不是"一种卡"，是"按场景长"的卡

同一个识别结果，进不同场景 → **长成不同的卡**（题头、事实行标签、追问、动作全随场景走）：

| 场景 | 题头 | 事实行 | 动作 |
|---|---|---|---|
| 出行 | 拾意 · 出行 | **出发** · 10月14日周三 / **目的地** · 深圳市 | 确认行程 / 改一下 |
| 会面 | 拾意 · 会面 | **时间** · 10月6日 15:00 / **地点** · 杭州 | 加进日程 / 回复对方 |
| 代办 | 拾意 · 代办 | **去哪** · 上海 | 记下来 / 转给别人 |
| 采买 | 拾意 · 采买 | **什么时候** · 10月10日 周六 | 去比价 / 先放着 |
| 提醒 | 拾意 · 提醒 | **什么时候** · 10月13日 周二 | 设提醒 / 改时间 |

**连"该问什么"也随卡型**：提醒卡不问"什么地方"，代办卡"去哪"已经定了就不再问。
**加一种场景 = 注册一条卡型定义**（`INTENT_ADAPTERS`），排版/渲染/门禁引擎一行不动。

## 二·六、交付的不是脚本，是一个能用的应用（真机跑过）

生成器是"跑完吐个包给你看"的**工具**。真正能上手的是
**`apps/shiyi-live/`：一个脚本应用**（`main.splash`，OctoScript）——有逻辑、能交互。

| 用户做什么 | 应用做什么 |
|---|---|
| 在输入框写一句话，或点例子胶囊 | **本机**识别出时间/地点/类型 |
| — | 卡**当场长出来**，题头/行标签/动作随场景不同 |
| — | **时间给真日期**：`下周三` → `下周三 · 10月14日`；`周末` → `这个周末 · 10月10日` |
| 点主按钮（确认行程 / 去比价 / 设提醒…） | 回执"已记下，等你点头再动"，另给一个「再来一张」 |
| 点「改一下」 | 卡收起来、句子留着，改完再点造卡 |
| — | 底部列出**本会话造过的卡**（最新在前）；整页可滚动 |

**Rinx 真机端到端跑通**：导入 bundle → Review → Run → 点例子 → 出卡 → 确认 → 再造一张。
证据：`docs/evidence/live-app/*.png` + `build/_gen_video/live-app-in-rinx.mp4`
（`build/record_rinx_app.py` 直接抓 Rinx 窗口，每帧都是宿主真实绘制；主按钮位置是**按颜色现场找的**，
因为卡片高度随内容变，写死坐标会点空）。

**离线完整可用**：识别全在本机，**不依赖任何服务** —— 正是官方"服务不可用时应用也要可用"那条。
（顺带实测：Rinx 这一版的导入页已经带「Assistant (this device)」，可配 provider / Base URL / Key，
`primary: ready` —— 那就是把本机规则换成模型该走的通道，**我们还没接**。）

## 二·七、长期记忆：**"拾意"就是意图，没有记忆就谈不上知道用户**

**这就是生成器能力②（长期记忆）在应用里的落地**，而且是**同一套 schema**
（`version / prefs / places / log`），app 写出来的文件生成器读得懂，反过来也行。

| 用在哪 | 具体 |
|---|---|
| **卡上给「记忆行」** | `记忆 · 你不坐飞机 → 这次只给高铁`、`记忆 · 深圳 通常早班` |
| **冲突提醒** | `⚠ 记忆里说「周三下午别安排」→ 这次要不要改天？` —— 记忆**主动纠正**你 |
| **确认 = 记住** | 写 `log`、记 `places`（保留原有字段）、从原文学几条明确偏好 |
| **给模型当上下文** | `mem_brief()` 把记忆拼成一段话 —— **接上设备助手时，这段随用户那句话一起发过去** |

**真机实测（Rinx，从零记忆开始）**：

1. 记忆条：`长期记忆 · 记住 0 张卡`；
2. 点一下「我不坐飞机」→ **习惯卡**「这是一条习惯 —— 确认就记住」；
3. 点确认 → 记忆条变成 **`记住 1 张卡 / 你：不坐飞机`**；
4. 再说「下周三我得去趟深圳」→ 出行卡上多一行 **`记忆 · 你不坐飞机 → 这次只给高铁`**；
5. 确认 → **`记住 2 张卡 / 常去：深圳 · 去过 1 次`**。

**关掉再打开，这些都还在**（文件在应用的 jail 里）。也实测能直接读生成器那份
`.local-state/memory.json`（界面立刻显示 `你：偏好高铁 · 不坐飞机 · 周三下午别安排`）。

**刻意不做的事**：偏好只认几条明确说法（不坐飞机 / 高铁 / 周三下午别安排），**不猜**隐含偏好。

## 二·八、接 AI：**代码已就位，默认关**（刘总 10-05 定："复赛肯定要接，不是现在接"）

按官方 `AI-SERVICES.md` 的 `model.complete` 契约写好了整条路，**两个开关都默认关**：

```splash
host.request("model.complete", {
    task:   model_task()                    // 要它干什么
    input:  {text: t memory: mem_brief()}   // ← 用户那句话 + 长期记忆，都进这里
    schema: model_schema()                  // 回复必须过 JSON Schema 才被接受
    class:  "fast"
}, fn(r){ if r.is_ok { apply_model_output(r.data.output, t) } else { identify_rules(t) } })
```

| 开关 | 现在 | 复赛 |
|---|---|---|
| `ASK_MODEL` | `false` —— 一律本机规则，**行为与 0.4.0 完全一致** | 改 `true` + 重盖摘要，就真调设备助手 |
| `MODEL_STANDIN` | `false` | 保持 `false`（仅本地验证用：从 jail 的 `model-stub.json` 读回复，走**同一条**解析路径） |

**本地验过三种状态**（都出图，见 `docs/evidence/model-path/`）：

| 状态 | 结果 |
|---|---|
| 默认 | `识别来源 · 本机规则（不依赖任何服务）` —— 与 0.4.0 一字不差 |
| **真回退**（`ASK_MODEL=true`，card-host 没有 model 服务） | 卡照出，来源写 `本机规则（设备助手不可用）` |
| **走模型**（再加替身） | 卡按**回复**长：`目的地 · 慕尼黑` —— 规则认不出这个城市 |

**最值钱的一张证据是 `payload-sent-to-model.json`**（替身把"本该发出去的载荷"也落盘）：
```json
{"input":{"text":"下个月初得去趟慕尼黑看展会",
          "memory":"用户长期记忆：偏好：坐高铁、不坐飞机、周三下午别安排。常去 深圳 · 通常早班。"}}
```
⇒ **长期记忆确实随那句话一起送进模型** —— 这就是"拾意 + AI"该有的样子。

**不启用时的行为**：一个字都不变（卡上照旧写"本机规则（不依赖任何服务）"），
**也绝不把用户的话发给任何助手**。官方那条"不可用时应用也要完整可用"始终成立：任何
`r.is_ok == false` 都回退，不重试、不挡路。

## 三、两条识别路（都能出卡，卡片自己标注走的是哪条）

官方现状：**没有 Shell 提供 `model` 服务**（Rinx 这一版导入页出现了「Assistant (this device)」并显示
`primary: ready`，但我们的应用还没接它）⇒ 应用侧的模型路仍是关的。所以识别层
按官方 `model.complete` 契约做成"有则用、无则退"：

| | 走模型（助手可用） | 回退规则（助手不可用） |
|---|---|---|
| 触发 | 宿主应答 `model.complete` | 无宿主应答 / 回复不合 schema / 失败 |
| 卡片标注 | `识别来源 · 设备助手` | `识别来源 · 本地规则` |
| 下游 | **完全同构** —— 排版/渲染/门禁一行都不用改 | 同左 |

**同一句话，两条路的差别**（`下个月初得去趟慕尼黑看展会`）：

| | 规则 | 模型 |
|---|---|---|
| 时间 | **认不出**（—） | **下个月初** |
| 地点 | **认不出**（正则把"慕尼黑看"一起吞了） | **慕尼黑** |
| 卡面结果 | 缺地点 + 追问两问 | 齐了，无需追问 |

## 五、和官方是什么关系

- **ADR 0006「App Studio on the phone」**：官方 2026-10-03 接受、**实现未开始**，且现有
  生成链绑在 Mac（需 Apple Vision 做 OCR）。
- 我们给的是另一条入口：**"意图 → 卡片"**（正是赛题名 The Intent Is the App），
  依赖换成本机 / Windows。
- 识别层照官方 `model.complete` 契约接：单次调用、回复须合 schema、**应用看不到提供方
  与密钥**、**不可用就回退且不重试**（官方硬要求）。

## 六、边界（照实）

- 做的是**「结构化意图 → 组件库组装」**，不是"任意意图 → 任意 UI"（官方自己
  App Studio 也分里程碑）。
- 覆盖**单屏确认卡 + 五屏流转**；**"图 → 卡片"**这一路（官方 image-to-card）**不做**。
- 生成器**不产出提交物**：产出在 `build/_gen/`；冻结的 `bundle/` 与 tag `v0.3.2`
  **一字节不动**。
- 本机模型这条路是**开发期桥**（`src/host_local.py`）；真机上由宿主决定有没有模型，
  应用不依赖它。
